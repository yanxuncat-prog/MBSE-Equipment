# 数据录入流程与方法

## 概述

本项目的设备数据来源于多份 Excel 表格，经过两个阶段导入到 PostgreSQL 数据库：

```
Excel 表格 ──(阶段一)──► SQLite 中间库 ──(阶段二)──► PostgreSQL 生产库
                ↓                              ↓
         data_import/ 下的脚本         backend/scripts/ 下的脚本
```

**阶段一**早期使用，将 Excel 按步骤逐表导入 SQLite，用于数据验证和调试。
**阶段二**是最终方案，直接从 Excel 读取并写入 PostgreSQL，用于生产环境。

## 阶段一：Excel → SQLite（数据验证阶段）

### 工具

- **导入脚本**: `data_import/server.py` — 零依赖 Web 查看器，端口 8899
- **查看页面**: `data_import/index.html` — 浏览器查看 SQLite 数据
- **导入指南**: `data_import/导入指南.md` — 逐步骤操作记录

### SQLite 数据库

| 文件 | 内容 |
|------|------|
| `data_import/equipment_X号构型.db` | X 构型完整数据（558 条设备 + 子表） |
| `data_import/equipment_1&2号构型.db` | 1&2 构型完整数据（439 条设备 + 子表） |

### SQLite 表结构

```
设备 (主表, 宽表, 62 列)
│  设备名称 ← 主键
│  基础信息 + 托架 + 电搭接 + 设备架接口 + 温度鉴定 + 重量 + 惯量
│
├──< 负载电气特性 (子表)
│     负载ID ← 主键
│     设备名称 → 设备.设备名称
│     同一设备可有多条（不同电压/功能通道）
│
├──< 负载工作模式 (子表)
│     负载ID + 工作模式 ← 复合主键
│     G0~G8 飞行阶段 0/1 矩阵
│
└── 飞行阶段定义 (维度表)
      阶段编号 ← 主键 (G0~G8)
      含同时系数等人工输入参数
```

### 导入步骤（8 步）

每步以 **设备名称** 作为匹配键，匹配不上的跳过并记录到 `未录入数据.md`。

| 步骤 | 来源 Sheet | 匹配方式 | 导入目标 |
|------|-----------|----------|----------|
| 1. 主表基础数据 | 主清单 → 对应构型 sheet | 设备名称为主键 | 主表 62 列 |
| 2. 托架信息 | 主清单 → 托架信息 | K 列匹配设备名称 | 托架名称、锁紧器、特殊需求等 |
| 3. 设备架接口 | 主清单 → 设备架接口信息 | 设备名称匹配 | 布置位置、安装方式、电搭接方式(设备架) |
| 4. 电搭接统计 | 主清单 → 电搭接情况统计 | B 列匹配设备名称 | 安装图、搭接形式/类型/阻值/位置 |
| 5. 负载电气特性 | 负载统计表 → 负载电气特性 | 负载 ID 主键，设备名称关联 | 工作功率、峰值功率、电压等级 |
| 6. 飞行阶段 + 工作模式 | 负载统计表 → 多个 sheet | 负载 ID + 工作模式复合主键 | G0~G8 矩阵、同时系数 |
| 7. 温度鉴定 | 温度.xlsx | 设备名称匹配 | DO-160 等级、鉴定温度范围、报告编号 |
| 8. 重量数据 | 重量表单模板.xlsx | 设备名称匹配 | 实测重量、重心、惯量 |

### 跳过数据记录

- `data_import/未录入数据_X构型.md` — X 构型跳过项
- `data_import/未录入数据_12号构型.md` — 1&2 号构型跳过项

**常见跳过原因**：
1. 设备名称在主表中不存在（其他构型独有设备）
2. 设备名称写法不同（如 `涵道风扇1` vs `涵道风扇1（金属）`）

## 阶段二：Excel → PostgreSQL（生产导入）

### 迁移脚本

| 脚本 | 说明 | 数据源 |
|------|------|--------|
| `backend/scripts/import_real_data.py` | **最终使用的脚本** — 直接从 Excel 导入 PostgreSQL | EXCEL数据/ 目录 |
| `data_import/migrate_to_sqlite.py` | SQLite → SQLite（中间格式转换） | SQLite 中间库 |
| `data_import/migrate_sqlite_to_pg.py` | SQLite → PostgreSQL（早期版本，每构型独立设备集） | SQLite 中间库 |
| `data_import/migrate_strict.py` | SQLite → PostgreSQL（严格映射版） | SQLite 中间库 |

### 最终导入流程（import_real_data.py）

这是生产环境使用的脚本，执行 5 个步骤：

```
1. reset_and_init()          — DROP + CREATE 所有表
2. create_base_data()        — 创建用户、项目、区域、母线
3. import_main_list()        — 从主清单导入设备（两个构型 sheet）
4. import_supplier_and_ata() — 从 0号机表补充供应商、英文名、DAL、接地等
5. import_temperature_data() — 从温度表补充 DO-160 鉴定数据
6. import_bonding_data()     — 从 0号机表补充电搭接数据
7. create_configurations()   — 创建 3 个构型，每个构型关联全部设备
```

### 运行方式

```bash
# 在后端容器内执行
docker compose exec backend python scripts/import_real_data.py
```

### 设备匹配策略

主清单中的设备通过 **part_number**（设备编号/DOORS编号）进行跨表匹配：

- 第一个构型 sheet 创建设备记录
- 第二个构型 sheet 如果 part_number 已存在，则补充缺失字段（不覆盖已有值）
- 补充数据表（0号机、温度）也以 part_number 匹配，仅填充空字段

### 件号生成规则

```python
# 有设备编号 → 直接使用
part_number = "2350E01001G900"

# 有 LIN 号但没有设备编号 → 使用 LIN 号
part_number = "3403U2501"

# 两者都没有 → 自动生成
part_number = "UNNAMED-{8位随机hex}"  # 后续已清理
```

### 构型区域映射

```python
ZONE_MAPPING = {
    "机头":       ("100", "机头段"),
    "驾驶舱":     ("110", "驾驶舱"),
    "下机身前段":  ("120", "下机身前段"),
    "客舱":       ("140", "客舱段"),
    "机翼":       ("200", "机翼段"),
    "短舱":       ("300", "短舱/发动机"),
    "尾段":       ("400", "尾段"),
    "设备架":     ("110", "驾驶舱"),
    ...
}
```

### 布尔值转换

中文布尔值统一转换规则：

```python
"是" / "有" / "1" → True
"否" / "无" / "0" → False
```

## 重新导入操作清单

如果需要重新导入全部数据：

```
□ 1. 确保 EXCEL数据/ 目录下有所有源文件
□ 2. docker compose exec backend python scripts/import_real_data.py
□ 3. 检查输出中的导入数量是否正确
□ 4. 手动删除 UNNAMED-* 和 #REF! 脏数据（参见上方"数据清洗"章节）
□ 5. 验证：SELECT count(*) FROM equipment; → 应为 265
□ 6. 导出备份：./scripts/db-export.sh
□ 7. 提交 data/aeroequip_dump.sql 到 Git
```
